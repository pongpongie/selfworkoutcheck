# 시현 트레이닝 PWA

주 4일 상하체 2분할 루틴 + 자유 요일(엑스트라) 앱.
정적 파일 몇 개 + 서비스워커. 빌드 도구도 의존성도 없다.

## 파일

```
index.html              UI · 이벤트 · 스타일
core.js                 순수 로직 (원판 계산, 기록 조회, 백업 검증, 그래프, 검색, 캘린더)
exercises.js            부위별 운동 종목 카탈로그 (데이터만)
test.js                 core.js · exercises.js 단위 테스트
manifest.json           PWA 매니페스트
sw.js                   서비스워커 (오프라인 캐시)
icon-192.png            아이콘
icon-512.png            아이콘
icon-512-maskable.png   안드로이드 어댑티브 아이콘
```

`core.js`는 DOM도 localStorage도 건드리지 않는다. 브라우저에서는 `window.Gym`,
node에서는 `module.exports`로 노출돼서 같은 코드를 그대로 테스트할 수 있다.

## 테스트

```bash
node test.js
```

의존성 없이 돈다. 종료 코드 0이면 통과.

## 배포

서비스워커는 **HTTPS 또는 localhost**에서만 등록돼. 파일을 그냥 더블클릭해서
`file://`로 열면 PWA 기능이 동작하지 않는다.

### 로컬 테스트

```bash
cd 폴더
python3 -m http.server 8080
# http://localhost:8080 접속
```

### GitHub Pages

```bash
git add .
git commit -m "gym pwa"
git push
```

저장소 → Settings → Pages → Source를 `main` / `root`로 지정.
`https://<계정>.github.io/<저장소>/` 로 접속된다.

### Vercel

```bash
npx vercel --prod
```

빌드 설정 없이 정적 파일 그대로 올라간다.

## 설치

- **Android / Chrome** — 주소창 메뉴 → "앱 설치"
- **iOS / Safari** — 공유 → "홈 화면에 추가" (Chrome 아님, Safari로 열어야 함)

## 기능

| 기능 | 설명 |
|---|---|
| 운동 기록 | 종목을 탭하면 세트별 중량·반복수 입력창이 열림. 입력 즉시 저장 |
| 지난주 비교 | 종목 카드에 직전 세션 기록이 표시됨. "지난 기록 불러오기"로 그대로 채우기 |
| 휴식 타이머 | ✓ 누르면 종목별 휴식 시간으로 자동 시작. 종료 시 비프 + 진동 |
| 중량 추이 | "기록 · 그래프" 탭에서 종목별 최고 세트 중량 추이 확인 |
| 캘린더 | "캘린더" 탭에서 월별로 운동한 날을 한눈에. 날짜를 누르면 그날 한 종목·세트·볼륨 |
| 종목 검색 | 부위 칩으로 좁히고 이름·초성·영문으로 검색. 고르면 세트·반복·휴식이 자동으로 채워짐 |
| 종목 추가 | 각 Day 하단에서 추가/삭제. 검색에 없는 이름은 직접 입력해도 됨 |
| 엑스트라 | 정해진 종목이 없는 자유 요일. 워밍업·어깨 서킷을 강제하지 않는다 |
| 날짜 바꾸기 | 각 Day 상단에서 기록할 날짜를 옮길 수 있음. 지난 날짜로 돌려 적기 가능 |
| 설정 | "설정" 탭에서 캐시 비우기·업데이트 확인·저장 공간 확인 |
| 백업 | 설정 → 데이터에서 JSON 내보내기 · 불러오기 · 전체 삭제 |
| 폼 영상 | 종목별 유튜브 검색을 새 탭으로 열기 |
| 원판 계산 | 바벨 종목은 봉 20kg 기준 한쪽 원판 구성을 자동 표시 |
| 오프라인 | 한 번 열면 신호 없어도 실행됨 |
| 키보드 | 종목 카드는 Tab으로 이동, Enter/Space로 펼치기 |

## 데이터

`localStorage`에 저장된다. 키는 두 개.

```
gym.logs.v1     { 종목ID: [ { date, sets:[{w,r,done}] } ] }
gym.custom.v1   { dayID: [ 추가한 종목 ] }
```

값이 하나도 없는 세션은 저장하지 않는다. 종목을 눌러 카드를 펼치기만 해서는
아무것도 쌓이지 않고, 실제로 중량·반복수를 넣거나 ✓를 눌러야 기록이 생긴다.

중량 칸의 회색 숫자는 **placeholder 라 값이 아니다.** 그래서 횟수만 적고 넘어가면
중량이 비어 볼륨이 0 이 된다. 이걸 막으려고, 횟수를 넣었는데 중량이 비어 있으면
**카드에 적힌 계획 중량을 실제 값으로 채워 넣는다.** 입력창에도 그 숫자가 뜨니
실제로 다른 무게를 들었으면 바로 고치면 된다. 맨몸 종목(계획 중량 0)은 채우지 않는다.

### 저장 시점과 날짜

**저장 버튼이 없다.** 칸에 값을 넣는 순간 `localStorage` 에 들어간다.

```
세트 칸에 45 입력 → change
  → ensureEntry("d1-bench", "2026-08-10", 4)   ← 날짜 = 입력한 그 순간의 로컬 날짜
  → saveLogs()
```

기록은 **종목이 바깥, 날짜가 안쪽**으로 쌓인다. 캘린더는 이걸 날짜 기준으로 뒤집어
(`Gym.buildCalendar`) 그린다. 별도의 "운동 세션" 레코드는 없고,
**그날 뭔가 입력했으면 그날 운동한 것**으로 본다.

### 기록 날짜 바꾸기

기본은 오늘이지만, 각 Day 상단의 날짜 바에서 다른 날짜로 돌려 적을 수 있다.
헬스장에서 못 적었거나 자정을 넘겨 마저 적을 때 쓴다.

```
‹  2026-08-07  ›        ← 하루씩 이동, 가운데를 누르면 달력에서 직접 고르기
07/15(수) · 26일 전에 기록 중   [오늘로]
```

오늘이 아닐 때는 날짜 바가 호박색으로 바뀌고 상단에도 `← 기록 중` 이 붙는다.
엉뚱한 날에 적고 있는 걸 모르고 지나치지 않게 하려는 것.

**앞날에는 기록할 수 없다.** 아직 하지 않은 운동을 적을 일이 없기 때문이고,
날짜 입력창에도 `max` 가 걸려 있다.

캘린더에서 날짜를 누르고 **"이 날짜에 기록하기"** 를 눌러도 같은 곳으로 간다.

### 백업

브라우저 데이터를 지우면 기록도 사라진다. 하단 **데이터 백업 → 내보내기**로
JSON 파일을 받아두면 된다.

```json
{
  "v": 1,
  "exportedAt": "2026-08-07T09:00:00.000Z",
  "logs": { "d1-bench": [ { "date": "2026-08-07", "sets": [ { "w": 45, "r": 8, "done": true } ] } ] },
  "custom": { "d1": [ { "id": "x-1754...", "name": "풀오버", "load": 20, "unit": "kg", "sets": 3, "reps": "12회", "rest": 60 } ] }
}
```

**불러오기는 덮어쓰지 않고 합친다.** 같은 종목·같은 날짜만 파일 쪽 값으로 바뀌고
나머지는 그대로 남는다. 들여온 값은 전부 검증·클램프를 거치니 손상된 파일을
넣어도 앱이 깨지지 않는다.

저장 공간이 가득 차면 조용히 넘어가지 않고 상단에 빨간 배너로 알려준다.

## 캘린더

월 격자에서 기록이 있는 날은 초록으로 칠해진다. 색이 진할수록 그 달에서 볼륨이
높았던 날이다. 오늘은 빨간 테두리, 선택한 날은 검게 반전된다.

날짜를 누르면 그날 한 종목이 볼륨 순으로 펼쳐지고, 왼쪽 색 막대가 부위를 나타낸다.
볼륨은 `중량 × 반복`의 합이라, 맨몸 종목은 볼륨 없이 세트 표시만 나온다.

## 종목 카탈로그

`exercises.js`에 8개 부위 144개 종목이 들어 있다.

```
가슴 20 · 등 22 · 어깨 17 · 이두 14 · 삼두 12 · 하체 27 · 코어 16 · 유산소·전신 16
```

검색은 세 가지로 걸린다.

```
벤치        이름 일부
ㅂㅊㅍㄹㅅ   초성 (부분 초성도 됨 — ㅅㅋㅌ → 스쿼트류)
deadlift    영문 별칭
```

같은 단어로 이어지는 쪽이 먼저 나온다. "벤치"를 치면 `벤치프레스`가 `벤치 딥스`보다 위다.

카탈로그에서 고른 종목은 카탈로그 id(`lib-*`)를 그대로 쓴다. 그래서 같은 종목을
여러 요일에 넣어도 기록이 한 줄로 이어진다. 반대로 같은 날에 같은 이름을 두 번
넣는 건 막는다 — 어느 카드에 적었는지 헷갈리기 때문.

중량·세트·반복·휴식 기본값은 "여기서 시작해보라"는 제안일 뿐이다. 등록할 때
고쳐도 되고, 등록한 뒤 카드에서 바꿔도 된다.

## 알려진 제약

- **iOS 알림** — 홈 화면에 추가한 경우에만 가능. 현재는 비프음과 진동만 사용.
- **폼 GIF** — 운동 GIF는 대부분 저작권이 있어 포함하지 않았다. 유튜브 검색 링크로 대체.
- **동기화 없음** — 기기 간 기록 공유는 백업 파일을 내보내고 다른 기기에서
  불러오는 방식으로만 된다.
- **워밍업·어깨 서킷 ID 공유** — 4일 모두 같은 종목 ID를 쓴다. 진행 기록이 한 줄로
  이어지는 대신, 같은 날 두 세션을 하면 나중 것이 덮어쓴다.

### 타이머에 대해

휴식 타이머는 남은 초를 빼는 대신 **종료 시각을 잡아두고 매번 현재 시각과 비교**한다.
화면이 꺼져 틱이 누락돼도 돌아왔을 때 값이 맞다. 타이머가 도는 동안에는 Wake Lock으로
화면을 켜두고, OS가 잠금 중에 회수해 가면 복귀 시 다시 잡는다.
(Wake Lock은 iOS Safari 16.4 미만 미지원 — 이 경우 화면만 꺼지고 시간은 정확하다.)

## 설정 탭

PWA 로 설치하면 브라우저의 캐시 삭제 메뉴가 묻혀서 찾기 어렵다. 그래서 앱 안에 뒀다.

| 항목 | 하는 일 |
|---|---|
| 업데이트 확인 | 서비스워커에 새 버전이 있는지 물어본다 |
| 캐시 비우고 새로고침 | 캐시를 다 지우고 서비스워커를 해제한 뒤 새로고침 |
| 저장 공간 | 기록한 날·종목·세트 수, 기록 용량, 브라우저 할당량 |
| 데이터 | 백업 내보내기·불러오기·전체 삭제 |

**캐시 비우기는 앱 파일만 지운다. 운동 기록(`localStorage`)은 건드리지 않는다.**
기록까지 지우려면 데이터 → 전체 삭제를 써야 한다.

현재 캐시 이름은 `caches.keys()` 로 직접 읽어 표시한다. 버전 문자열을 따로
두지 않으니 `sw.js` 의 `CACHE` 하나만 관리하면 된다.

## 캐시 갱신

`index.html` · `core.js` · `exercises.js` 를 수정하면 `sw.js`의 `CACHE` 값을 올려야
확실히 반영된다.

```js
var CACHE = 'gym-v8';
```

서비스워커는 200 응답만 캐싱한다. 배포 중 404나 502가 떠도 그 응답이 캐시에 박히지 않는다.
